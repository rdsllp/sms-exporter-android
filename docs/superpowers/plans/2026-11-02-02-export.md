# SMS Exporter – Plan 2 of 3: Export (PDF, HTML, CSV, JSON, ZIP)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Export one or many conversations, scoped by the active filter, to PDF, HTML, CSV or JSON, with attachments handled per format, saved to Downloads and offered in the share sheet.

**Architecture:** Pure renderers (`HtmlRenderer`, `CsvWriter`, `JsonWriter`) turn `Conversation + List<Message>` into text and are unit-tested with fakes. `ImageScaler` and `PdfPrinter` are Android-side. `ExportCoordinator` runs an `ExportRequest` on a background coroutine, writes through `ExportSink` (MediaStore Downloads or a temp dir inside a ZIP), and reports `ExportProgress`. The UI adds an export sheet and a progress sheet used from both screens.

**Tech Stack:** as Plan 1, plus `java.util.zip`, `android.print` + `WebView` for PDF, MediaStore for Downloads.

**Spec:** `docs/superpowers/specs/2026-11-02-sms-exporter-design.md` (§6.1 export rules, §7 formats)

## Global Constraints

- Filters scope the export: the message set is exactly `MessageRepository.all(conversation, filter)`.
- Output root: `Downloads/SmsExporter/` via `MediaStore.Downloads` (`RELATIVE_PATH = "Download/SmsExporter"`), `IS_PENDING` while writing.
- File names: `<title sanitized>_<yyyy-MM-dd>.<ext>`; ZIP `SmsExporter_<yyyy-MM-dd_HHmm>.zip`; attachments `<messageRowId>_<n>.<ext>` inside `attachments/`.
- PDF/HTML embed images downsampled to max 1600 px long edge, JPEG quality 85; CSV/JSON copy original bytes.
- CSV: UTF-8 with BOM, first line `# SmsExporter export <ISO datetime> · filter: <describe or none>`, then the header row.
- JSON `conversation` object carries `exportedAt`, `filter`, `partial`.
- No network. Commit after every task.

## Review Focus

1. A title like `Axis Bank/Cards?` or `+91 98… ` must become a safe file name on both Android's FAT-style restrictions and ZIP; two conversations with the same title in one ZIP must not overwrite each other. (Task 1 test `sanitizeAndDeduplicate`)
2. A body with `"`, `,`, newline and a leading `=`/`+` must be CSV-safe (quoted, doubled quotes, formula-injection prefix neutralised with a leading `'`). (Task 3 test `csvEscapesDangerousCells`)
3. An attachment whose bytes cannot be read must not abort the export: the file is skipped, noted in the message's attachment entry as `missing: true`, and the export completes. (Task 5 test `missingAttachmentIsSkippedNotFatal`)
4. A conversation with zero messages after filtering must still produce a file saying so, not an empty file or a crash. (Task 2 test `emptyConversationRendersNotice`)
5. Cancelling mid-export must leave no half-written file in Downloads (pending entries deleted). (Task 6 instrumented `cancelLeavesNoPendingFiles`)

**Interfaces:**

```kotlin
object ImageScaler { fun toDataUri(bytes: ByteArray, maxEdgePx: Int = 1600, quality: Int = 85): String? }  // BitmapFactory with inSampleSize, then JPEG; null if undecodable
interface ExportSink : java.io.Closeable {
    fun open(path: String, mime: String): java.io.OutputStream     // path relative to export root, e.g. "Priya_2026-11-02/attachments/21562_1.jpg"
    fun finish(): Pair<android.net.Uri, String>                    // (uri of the single resulting item, display path)
    fun abort()                                                     // delete anything written
}
class DownloadsSink(contentResolver, subDir: String = "Download/SmsExporter") : ExportSink   // one MediaStore entry per open(); finish() returns the last/only entry; multiple files in a folder are not supported (coordinator uses ZipSink for those)
class ZipSink(contentResolver, zipFileName: String) : ExportSink                            // single pending MediaStore entry wrapping a ZipOutputStream; open() = putNextEntry
class AttachmentExporter(repo: MessageRepository) { fun copy(a: Attachment, sink: ExportSink, path: String): Boolean /* false when unreadable */ }
```

**Files:**

- Test: `app/src/test/java/com/example/smsexporter/export/ExportCoordinatorTest.kt` (fake repo, in-memory sink, fake printer)

**Interfaces:**

```kotlin
class ExportCoordinator(repo: MessageRepository, htmlRenderer: HtmlRenderer, pdf: suspend (String, OutputStream) -> Unit, sinkFactory: (ExportRequest) -> ExportSink, clock: () -> ZonedDateTime) {
    fun run(request: ExportRequest): kotlinx.coroutines.flow.Flow<ExportProgress>   // cancellable; cold
}
```

Rules: single conversation + PDF/HTML → `DownloadsSink`, one file. Single + CSV/JSON with ≥ 1 attachment, or any multi-conversation request → `ZipSink` with one folder per conversation (`FileNames.deduplicate` on folder names). Single + CSV/JSON with no attachments → `DownloadsSink`, one file. Per conversation: `messages = repo.all(conversation, filter).reversed()` (oldest first); for PDF/HTML build `image` lambda = `ImageScaler.toDataUri(bytes)`; for CSV/JSON copy attachments first with `AttachmentExporter` and pass names. Emit `Running` before each conversation and at 0.5 after messages load. On exception → `abort()` then `Failed`. On cancellation → `abort()` then `Cancelled`.
