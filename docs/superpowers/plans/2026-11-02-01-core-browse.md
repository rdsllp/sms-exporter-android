# SMS Exporter – Plan 1 of 3: Core data layer and browsing UI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only Android app that lists every conversation merged the way Google Messages does and opens any of them as a chat view with attachments, bot cards, reactions, search, filters, sort, and the four swipe gestures.

**Architecture:** Three layers. `data/` reads the Telephony provider through a small `MessageSource` interface and turns raw rows into `Conversation` and `Message` models with pure, unit-tested functions (normalize, merge, reaction parsing, bot cards, filters). `ui/` is Jetpack Compose + Material 3 with two screens (list, conversation) backed by ViewModels. Plans 2 and 3 add `export/` and `role/` on top of the same models.

**Tech Stack:** Kotlin 2.2, Jetpack Compose (BOM 2026.02.01), Material 3, navigation-compose, lifecycle-viewmodel-compose, Coil for images, kotlinx-serialization-json, JUnit 4 unit tests, androidx instrumented tests on the owner's Samsung.

**Spec:** `docs/superpowers/specs/2026-11-02-sms-exporter-design.md`

## Global Constraints

- `minSdk 29`, `compileSdk 37`, `applicationId com.example.smsexporter` (unchanged).
- No `INTERNET` permission, ever. Manifest permissions in this plan: `READ_SMS`, `READ_CONTACTS`, and the role-eligibility set already present (`RECEIVE_SMS`, `RECEIVE_MMS`, `RECEIVE_WAP_PUSH`, `SEND_SMS`).
- The app never writes to the Telephony provider in this plan.
- `content://sms` dates are milliseconds; `content://mms` dates are seconds. All models use milliseconds.
- RCS = `mms` row whose `tr_id` starts with `proto:`. Otherwise MMS. `sms` rows are SMS.
- Conversation merge key = sorted set of normalized addresses (spec §5.3).
- Home list visible within 1 s; conversation newest page within 300 ms on the Samsung dataset (22.8k messages, 2.96k raw threads).
- Build/test commands: `./gradlew :app:testDebugUnitTest`, `./gradlew :app:connectedDebugAndroidTest` (device attached), `./gradlew :app:installDebug`.
- Commit after every task. The repo is created in Task 1.

## Review Focus

1. A thread whose `recipient_ids` points at a canonical address that no longer exists must still appear (title = "Unknown"), not crash or vanish. (Task 5 test `unknownRecipientStillListed`)
2. A message body containing a comma, quote, or newline must survive search and display intact; search must be case-insensitive and match Unicode (Bengali text exists in the data). (Task 8 test `searchIsCaseInsensitiveAndUnicode`)
3. A received-reaction body whose quoted text matches nothing must still be shown, as its own bubble. (Task 6 test `unmatchedReactionStaysAsMessage`)
4. A bot-message JSON that fails to parse must fall back to image + any text, never an empty bubble. (Task 7 test `malformedBotJsonFallsBack`)
5. An attachment part whose `_data` file is missing on disk must render as a broken-file chip, not crash the list. (Task 10 instrumented check `missingAttachmentDoesNotCrash`)

data class RawMms(val id: Long, val threadId: Long, val msgBox: Int, val dateMs: Long, val trId: String?, val contentType: String?, val textOnly: Boolean)

interface MessageSource {
    suspend fun threads(): List<RawThread>
    suspend fun canonicalAddresses(): Map<Long, String>
    suspend fun sms(threadIds: Collection<Long>, where: RowFilter, limit: Int, beforeMs: Long?): List<RawSms>
    suspend fun mms(threadIds: Collection<Long>, where: RowFilter, limit: Int, beforeMs: Long?): List<RawMms>

Chunk `IN (...)` lists to ≤ 500 ids per query. Run queries on `Dispatchers.IO`.

data class MessageFilter(val startMs: Long? = null, val endMs: Long? = null, val query: String? = null,
                         val hasAttachment: Boolean = false, val kind: MessageKind? = null) {
    val isActive: Boolean
    fun toRowFilter(): RowFilter        // start/end/query only; attachment + kind are applied in memory
    fun describe(): String              // "Jan 1 – Oct 31 2026 · "axis" · attachments only" or "" when inactive
}
class MessageRepository(private val source: MessageSource, private val names: NameLookup) {
    suspend fun conversations(refresh: Boolean = false): List<Conversation>  // ConversationIndex.build + lastKind from newest row; cached in memory after first load
    suspend fun conversation(key: String): Conversation?                   // from the cache
    suspend fun page(conversation: Conversation, filter: MessageFilter, beforeMs: Long?, limit: Int = 200): List<Message>  // newest first, both tables merged by timestamp, reactions attached, bot cards parsed
    suspend fun count(conversation: Conversation, filter: MessageFilter): Int

}

Mapping rules: SMS `type` 1→RECEIVED, 2→SENT, 5→FAILED, others→SENT. MMS `msg_box` 1→RECEIVED, 2→SENT. RCS detection by `trId`. `body` for mms = concatenation of `text/plain` parts' `text` in `seq` order. `attachments` = parts whose `ct` is not `text/plain`, `application/smil`, or the bot JSON. Address for mms: `addrs` row with type 137 for received, first type 151 for sent. `kind` filter and `hasAttachment` are applied after the row fetch; when they are set, the repository keeps paging until `limit` matching messages are found or rows run out.
